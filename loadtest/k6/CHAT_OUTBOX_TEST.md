# 채팅 아웃박스 제거 전후 측정

채팅 메시지의 실시간 전송을 아웃박스에서 분리했을 때 발신자 ACK 지연, 상대방 수신 지연, 수신 누락률이 어떻게 달라지는지 확인한다.

## 비교 환경

같은 PR Preview에 Before와 After를 순서대로 배포한다. Before는 기존 아웃박스 즉시 처리 경로를 사용하고, After는 메시지 저장이 커밋된 뒤 WebSocket으로 비동기 전송한다. 각 배포의 서버 커밋과 실시간 전송 설정을 기록한다. 기존 dev 측정값은 참고 자료로 사용한다.

## 부하 조건

| 항목 | 조건 |
|---|---|
| 시나리오 | k6 메시지 전송 단독 |
| 동시 사용자 | 한 방에 10명 또는 50명 |
| 전송 주기 | 사용자당 2.5초마다 1건. 전송 시작 시점을 10명은 250ms, 50명은 50ms 간격으로 분산 |
| 동시 요청 | 사용자당 진행 중 요청 최대 1건. 처리 중에 다음 슬롯이 오면 전송 누락으로 기록 |
| 측정 시간 | 워밍업 30초, 본측정 120초, 회차 사이 대기 30초 |
| 본측정 전송량 | 사용자당 48건 예정. 회차당 10명은 480건, 50명은 2,400건 |
| 실행 횟수 | 버전별로 10명과 50명 조건을 각각 3회 실행 |
| 테스트 데이터 | 전용 회원을 준비하고 매 회차 새 방을 사용한다. 측정 후 생성한 방과 회원을 정리한다. |

## 결과 집계

- 발신자 전송 시각부터 ACK 수신과 상대방 WebSocket 수신까지의 시간을 각각 측정한다. 회차별 평균·p95·p99를 구하고 각 지표의 3회 평균을 기록한다.
- 실제 전송 건수, ACK 실패, 예정 전송 누락, 수신 누락과 중복을 기록한다. 메시지마다 발신자를 제외한 방 인원을 기대 수신자로 계산한다.
- Grafana에서 본측정 구간의 Hikari 커넥션 획득 대기시간과 대기 요청 수를 확인한다. PostgreSQL 락을 수집할 수 있다면 두 버전에서 동일하게 200ms 간격으로 관측한다.

실행 방법과 지표 이름은 [채팅 부하 테스트 가이드](CHAT.md)를 참고한다.
