# Challenger Domain

## 역할

`challenger` 도메인은 UMC 활동자의 기수별 활동 기록, 파트, 상태, 상벌점을 관리한다. 일정 생성, 출석, 프로젝트 지원 등 여러 기능의 자격 판단에 사용된다.

## 책임

- 챌린저 활동 기록을 생성하고 수정한다.
- 기수, 학교, 파트 기준으로 챌린저를 조회한다.
- 상벌점을 부여, 수정, 삭제한다.
- 챌린저 상태와 기록 추가 코드를 검증한다.

## 경계

회원 정보는 `member`, 조직 정보는 `organization` 도메인의 책임이다. 챌린저 도메인은 다른 도메인의 Aggregate를 직접 참조하지 않고 ID와 공개 UseCase를 통해 필요한 정보만 사용한다.

## 11기 Part 전환

- 기본 파트는 `PLAN`, `DESIGN`, `WEB_PRODUCT_ENGINEER`, `MOBILE_PRODUCT_ENGINEER`를 사용한다.
- `V2026.09.15.00.00`은 `generation=11`인 기수의 챌린저·등록 코드·커리큘럼·스터디그룹에서 기본 Track을 같은 이름의 Part로 복사한다. 이전 기수의 학습 정보와 기존 행의 식별자·등록 코드 사용 이력은 보존한다.
- 챌린저와 등록 코드의 수강 Track은 하나여야 한다. 복수 Track이나 `INFRA_PLUS`를 발견하면 복사를 중단하며, 비수강 운영진의 빈 배열은 변경하지 않는다.
- 운영진 등록 코드의 기존 담당 Part와 수강 Track이 다르면 담당 파트를 덮어쓰지 않고 복사를 중단한다.
- 원본 `track`/`tracks` 컬럼과 리크루팅의 Track 계약은 유지한다. 리크루팅 등록 경계에서 `ChallengerTrack.toPart()`로 변환하고, 챌린저 학습 정보는 Part로 저장한다.
- `INFRA`는 독립 Part로 사용하지 않고 개인별 `infra` boolean을 유지한다. 학습 기준을 Part로 통일해 기수의 `learningType`은 제거한다. 리크루팅의 Part 전환과 Track 컬럼 제거는 후속 작업이다.

## 상벌점 검증과 앱 전환

상벌점 부여는 유형별 배점과 대상 기수의 정책을 검증한다. 고정 유형의 배점 불일치와 CUSTOM 점수 누락을 거절하며, 10기부터는 구형 `BEST_WORKBOOK`의 신규 부여를 거절한다. 기수 기준은 `gisuId`의 숫자가 아니라 `generation`이다.

`BEST_WORKBOOK`의 기본 배점은 -0.5점이고 `BEST_WORKBOOK_V2`는 +2점이다. 서버가 구형 요청을 V2로 자동 변환하면 배점 의미가 달라질 수 있으므로 요청 유형을 임의로 바꾸지 않는다. 오류 `CHALLENGER-0021`은 사용자에게 해당 기수에서 사용할 수 없는 항목임을 안내하고, 구체적인 API 타입 선택은 앱에서 처리한다.

기존에 성공하던 요청이 새롭게 400을 받을 수 있으므로, 검증 변경은 다음 순서로 배포한다.

1. 지원하는 앱 버전에서 10기 이상 우수 워크북 부여 시 `BEST_WORKBOOK_V2`를 보내도록 전환한다. 고정 유형은 배점을 생략하거나 기본값과 같은 값을 보내고, CUSTOM은 점수를 반드시 보낸다.
2. 앱에서 정상 부여 및 오류 응답 처리를 확인한다. 구형 타입 차단만 해제해도 `BEST_WORKBOOK`에 +2점을 보내는 요청은 고정 배점 검증에 걸리므로 두 조건을 함께 확인한다.
3. 앱 전환 확인 후 서버 검증 변경을 배포한다. 지원 중인 구버전 앱의 전환이 확인되지 않으면 배포를 보류한다.

과거에 저장된 구형 유형과 개별 배점, 기존 응답 필드는 이 전환으로 변경하지 않는다.

## UX Writing Notes

`사용자`보다 도메인 의미가 분명한 `챌린저`를 우선한다. 코드, 기수, 소속이 맞지 않는 오류는 `입력한 코드를 확인해주세요`, `소속 정보를 확인해주세요`처럼 사용자가 바로 확인할 대상을 말한다.
