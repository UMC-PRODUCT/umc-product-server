# 학교별 닉네임 사용 가능 여부

회원가입 전 학교와 닉네임을 입력하면 해당 학교에서 닉네임을 사용할 수 있는지 조회한다.
입력 중 자동 조회와 별도 중복 확인 버튼 모두 같은 API를 사용한다.

## 요청

`GET /api/v1/member/nicknames/availability`

로그인하지 않은 사용자도 호출할 수 있다. 전역 API 요청 제한은 동일하게 적용된다.

| 쿼리 파라미터 | 필수 | 조건 |
| --- | --- | --- |
| `schoolId` | O | 존재하는 학교의 양의 정수 ID |
| `nickname` | O | 공백 없는 완성형 한글 1~4자. 앞뒤 공백도 허용하지 않음 |

```http
GET /api/v1/member/nicknames/availability?schoolId=1&nickname=토리
```

조회 API와 이메일·OAuth 신규 회원가입에 같은 닉네임 입력 규칙을 적용한다.
신규 회원가입의 이름은 1~5자로 제한한다.
기존의 중복 닉네임이나 4자 초과 닉네임은 변경하지 않는다.

## 판정 범위

- 같은 학교의 모든 저장 회원을 검사한다. 이름과 파트는 중복 판정 조건이 아니다.
- 기수와 챌린저 등록 여부에 따른 필터가 없다. 이전 기수 회원과 챌린저 이력이 없는 회원도 포함한다.
- 활동·휴면 회원은 포함한다.
- 탈퇴 회원은 기수·수료 이력과 관계없이 기존 닉네임을 다른 회원이 재사용할 수 없다.
- 탈퇴로 회원이 물리 삭제되면 학교·닉네임 예약 기록을 남겨 재사용을 제한한다.
- 다른 학교의 동일 닉네임은 사용할 수 있다.
- 같은 학교에 기존 중복 데이터가 여러 건 있더라도 조회는 성공하고 사용 불가로 응답한다.

## 응답

미사용 닉네임은 HTTP 200으로 다음과 같이 응답한다.

```json
{
  "success": true,
  "code": "COMMON200",
  "message": "성공입니다.",
  "result": {
    "available": true
  }
}
```

성공 응답의 공통 `code`와 `message`는 전역 성공 응답 규약을 따른다. 클라이언트는 `result.available`을 확인한다.
사용 중인 닉네임도 HTTP 200으로 응답하되 `available`은 `false`다. 중복 회원의 이름·이메일·회원 ID 등 개인정보는 반환하지 않는다.

| 상황 | HTTP 상태 | 설명 |
| --- | --- | --- |
| 필수 값 누락, 잘못된 ID·닉네임 | 400 | 기존 공통 요청 검증 오류 |
| 존재하지 않는 학교 | 404 | `ORGANIZATION-0018` |
| API 요청 제한 초과 | 429 | 기존 전역 API 요청 제한 |

## 최종 회원가입과의 관계

이 API는 조회 시점의 상태를 알려주며 닉네임을 예약하지 않는다. 사용 가능 응답 직후 다른 회원이 같은 닉네임으로 가입할 수 있다.
예약된 탈퇴 닉네임은 공개 조회에서는 사용 불가로 응답한다. 수료 탈퇴자의 본인 재사용 예외는 검증된 이메일을 가진 최종 회원가입에서 판정한다.

최종 이메일·OAuth 회원가입에서도 형식과 사용 가능 여부를 다시 검사한다. 사전 조회를 생략하거나 조회 후 다른 회원이 먼저 가입하면
중복 가입은 HTTP 409, `MEMBER-0020`으로 거절한다. 서비스 직접 호출 시 잘못된 닉네임은 HTTP 400, `MEMBER-0019`에 해당한다.
HTTP 요청의 필드 검증 오류는 기존 공통 요청 검증 응답을 따른다.

PostgreSQL 트랜잭션 advisory lock으로 같은 학교의 가입·탈퇴 처리를 직렬화한다. 중복 검사부터 저장까지 잠금을 유지하므로
이메일·OAuth가 동시에 같은 닉네임으로 가입해도 한 명만 성공한다. 배치는 학교 ID 오름차순으로 먼저 잠그며,
배치 내부의 중복도 전체 롤백한다. 기존 중복을 유지하기 위해 회원 테이블에는 유일 인덱스를 추가하지 않는다.
이 보장은 정상 등록 UseCase를 통과하는 가입에 적용된다. 운영 DB에 직접 쓰는 작업도 같은 정책과 잠금 규칙을 지켜야 한다.

## 적용 시점과 보존 범위

- 정책의 대상은 11기 신규 가입자부터다. 가입 요청 자체에는 기수가 없으므로 배포 이후 신규 가입부터 적용한다.
  기존 계정이나 이전 기수 기록을 수정하거나 현행 기수만으로 중복 조회 범위를 제한하지 않는다.
- 예약 테이블 `member_nickname_reservation`은 추가 Flyway 마이그레이션으로 생성한다.
  기존 회원·닉네임 데이터는 수정하거나 삭제하지 않는다.
- 이미 물리 삭제되어 학교·닉네임을 알 수 없는 과거 계정은 이번 작업만으로 복원할 수 없다.
  해당 계정의 예약이 필요하면 별도의 원본 데이터 확인과 이관이 필요하다.
- 기존 회원은 닉네임을 변경할 수 없다. 학교 변경과 기존 중복 닉네임의 강제 정리는 범위에 포함하지 않는다.
- 미수료 탈퇴자는 재가입 시 새 닉네임을 사용할 수 있다. 수료 탈퇴자는 같은 검증 이메일로 재가입하며 기존 닉네임만 사용할 수 있다.
- 닉네임 예약에는 이메일 원문이 아닌 SHA-256 소유 키를 저장한다. 별도의 소셜 계정 찾기 플로우는 이번 배포에 포함하지 않는다.
- 개발용 시딩도 새 가입 규칙을 지키도록 시퀀스로 중복 없는 한글 4자 닉네임을 생성한다.
