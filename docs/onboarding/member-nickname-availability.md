# 학교별 닉네임 사용 가능 여부

회원가입 전 학교와 닉네임을 입력하면 해당 학교에서 닉네임을 사용할 수 있는지 조회한다.
입력 중 자동 조회와 별도 중복 확인 버튼 모두 같은 API를 사용한다.

## 요청

`GET /api/v1/member/nicknames/availability`

로그인하지 않은 사용자도 호출할 수 있다. 전역 API 요청 제한은 동일하게 적용된다.

| 쿼리 파라미터 | 필수 | 조건 |
| --- | --- | --- |
| `schoolId` | O | 존재하는 학교의 양의 정수 ID |
| `nickname` | O | 공백 없는 완성형 한글 1~6자. 앞뒤 공백도 허용하지 않음 |

```http
GET /api/v1/member/nicknames/availability?schoolId=1&nickname=토리
```

이번 작업은 기존 회원가입 입력 규칙을 유지한다. 피그마의 한글 1~4자 적용 여부와 기존 닉네임 변경 정책은 별도로 확정한다.

## 판정 범위

- 같은 학교의 모든 저장 회원을 검사한다. 이름과 파트는 중복 판정 조건이 아니다.
- 기수와 챌린저 등록 여부에 따른 필터가 없다. 이전 기수 회원과 챌린저 이력이 없는 회원도 포함한다.
- 활동·휴면·탈퇴 상태의 저장 회원을 모두 포함한다.
- 물리 삭제된 회원의 닉네임을 별도 보관하거나 예약하지 않는다.
- 다른 학교의 동일 닉네임은 사용할 수 있다.
- 같은 학교에 기존 중복 데이터가 여러 건 있더라도 조회는 성공하고 사용 불가로 응답한다.

## 응답

미사용 닉네임은 HTTP 200으로 다음과 같이 응답한다.

```json
{
  "success": true,
  "code": "COMMON200",
  "message": "성공입니다.",
  "result": {
    "available": true
  }
}
```

성공 응답의 공통 `code`와 `message`는 전역 성공 응답 규약을 따른다. 클라이언트는 `result.available`을 확인한다.
사용 중인 닉네임도 HTTP 200으로 응답하되 `available`은 `false`다. 중복 회원의 이름·이메일·회원 ID 등 개인정보는 반환하지 않는다.

| 상황 | HTTP 상태 | 설명 |
| --- | --- | --- |
| 필수 값 누락, 잘못된 ID·닉네임 | 400 | 기존 공통 요청 검증 오류 |
| 존재하지 않는 학교 | 404 | `ORGANIZATION-0018` |
| API 요청 제한 초과 | 429 | 기존 전역 API 요청 제한 |

## 최종 회원가입과의 관계

이 API는 조회 시점의 상태를 알려주며 닉네임을 예약하지 않는다. 사용 가능 응답 직후 다른 회원이 같은 닉네임으로 가입할 수 있다.

최종 회원가입의 중복 차단과 동시 가입 제어는 [#1458](https://github.com/UMC-PRODUCT/umc-product-server/issues/1458)에서 별도로 구현한다.
이번 [#1457](https://github.com/UMC-PRODUCT/umc-product-server/issues/1457)은 기존 회원가입 동작이나 기존 중복 계정 데이터를 변경하지 않는다.
