## 개요

PR을 리뷰할 때 쓰는 기준입니다. 사람 리뷰어와 AI 리뷰어가 같이 씁니다.

규칙 문장의 원본은 루트 [`AGENTS.md`](../../AGENTS.md)에 있고, 이 문서는 규칙을 번호(`ARCH-05` 같은)로만 가리킵니다.
규칙을 바꾸려면 `AGENTS.md`를 고치고, 이 문서는 우선순위·강제 수단·기각 기록만 고칩니다.

## 리뷰하는 순서

1. 변경 경로에 해당하는 루트 `AGENTS.md` 규칙과, 변경 경로에 가까운 하위 `AGENTS.md`를 읽습니다.
2. 아래 [기각된 지적](#기각된-지적)을 읽고, 같은 지적은 하지 않습니다.
3. 지적은 아래 형식으로 남깁니다.

```text
[P2][ARCH-05] 다른 도메인 Repository를 직접 주입합니다.
근거: monolith/src/main/java/.../ProjectApplicationCommandService.java:42
제안: member 도메인의 GetMemberUseCase를 주입합니다.
```

해당하는 규칙이 없으면 규칙 번호 자리에 `규칙 후보`라고 적습니다. 같은 `규칙 후보` 지적이 반복되면 `AGENTS.md`에 새 규칙으로 올릴지 논의합니다.

## 지적 우선순위

| 우선순위 | 대상 |
|---|---|
| P1 | 보안, 데이터 손실, 심각한 버그 |
| P2 | 아키텍처, 성능, 확장성 |
| P3 | 코드 품질, 컨벤션 |
| P4 | 다른 방법 제안 |
| P5 | 오타, 질문 |

## 규칙별 기본 우선순위와 강제 수단

"강제 수단"은 사람이 놓쳐도 무엇이 막아 주는지입니다. "리뷰"라고 적힌 규칙은 리뷰에서만 지켜집니다.

| 규칙 | 기본 우선순위 | 강제 수단 |
|---|---|---|
| AUTHZ-01 ~ AUTHZ-09 | P1 | 리뷰 |
| CONV-09 | P1 | 리뷰 |
| ARCH-01 ~ ARCH-05 | P2 | 리뷰. 일부 범위만 테스트로 막힙니다. `chat`·`community` 패키지 사이 의존은 `ChatCommunityDependencyArchTest`(ArchUnit), `:blog` 모듈이 다른 도메인 내부를 쓰는 것은 `BlogModuleBoundaryTest` |
| ARCH-06 ~ ARCH-09 | P2 | 리뷰 |
| CONV-01, CONV-19 | P2 | 리뷰 |
| CONV-20 | P3 | 일부. `./gradlew check`의 `checkDuplicateFlywayMigrationVersions`가 `V*__*.sql` 형식과 버전 중복을 막습니다. 날짜 형식은 리뷰 |
| CONV-02 ~ CONV-08, CONV-10 ~ CONV-18 | P3 | 리뷰 |
| TEST-01 ~ TEST-05 | P3 | 리뷰 |
| GIT-01 ~ GIT-03 | P3 | 리뷰 |

줄 길이, 들여쓰기 같은 서식은 Spotless와 Checkstyle이 `./gradlew check`에서 막으므로 리뷰에서 지적하지 않습니다.

## 기각된 지적

리뷰에서 나왔지만 팀이 맞지 않다고 판단한 지적입니다. AI 리뷰어는 같은 지적을 하지 않습니다.

| 날짜 | 지적 | 관련 규칙 | 기각 이유 | PR |
|---|---|---|---|---|
| (아직 없음) | | | | |

## 기준을 고치는 방법

리뷰 기준은 리뷰 결과에 따라 계속 바뀝니다.

1. 같은 지적이 서로 다른 PR 두 곳 이상에서 받아들여지면, 테스트나 린트로 막을 수 있는지 봅니다. 막았다면 위 표의 "강제 수단"을 고칩니다. pstack을 쓴다면 `/pstack:correct`가 이 작업을 합니다.
2. 지적이 기각되면 [기각된 지적](#기각된-지적)에 한 줄을 추가합니다.
3. `규칙 후보` 지적이 반복되면 `AGENTS.md`에 새 번호로 규칙을 추가합니다. 번호는 다시 쓰지 않습니다.
4. 한 달에 한 번 최근 PR의 리뷰 코멘트를 모아 이 문서를 점검합니다.

## AI 리뷰를 돌리는 방법 (선택)

PR을 올리기 전에 원하는 사람만 로컬에서 돌립니다. pstack을 쓴다면 다음처럼 요청합니다.

```text
/pstack:thermos docs/guides/코드_리뷰_기준.md 기준으로 이 브랜치를 리뷰해줘
```

AI 리뷰 결과도 위 형식과 우선순위를 따릅니다. 사람이 받아들이거나 기각한 결과가 이 문서를 고치는 근거가 됩니다.
