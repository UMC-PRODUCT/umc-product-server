# UMC PR 본문

먼저 읽는다: `docs/guides/PR_글쓰기_기준.md`, `.github/pull_request_template.md`, 루트 `AGENTS.md`의 `GIT-01`~`GIT-03`. 글쓰기 규칙은 기준 문서에 있고, 이 스킬은 본문의 뼈대와 순서만 정한다.

## 1. 본문을 쓴다

템플릿의 두 섹션을 그대로 쓰고 HTML 주석은 지운다. 전체를 약 40줄 이하로 쓴다. 넘치면 본문을 늘리기 전에 PR을 쪼갤 수 있는지 사용자에게 묻는다.

`## 🚀 작업 내용`

1. 첫 문단에 왜 하는지를 한두 문장으로 쓴다.
2. 기준 문서의 규칙 6에 해당하면 가장 작은 그림 하나를 넣는다. 요청 흐름과 외부 호출 순서는 Mermaid `sequenceDiagram`, 상태 전이는 `stateDiagram-v2`, 여러 모듈에 걸친 변경은 `flowchart`, 호출 순서 변화는 앞뒤 맥락을 남긴 `diff` 스케치, 파일 구조 변경은 경로마다 한 줄 설명을 붙인 짧은 트리로 그린다.
3. 동작이 바뀌는 PR이면 `**Before:**`와 `**After:**`를 한 줄씩 쓴다. 실제로 실행해서 본 결과만 쓴다.

`## 💬 리뷰 중점사항`

1. `봐 주세요:`로 사람이 판단할 일을 쓴다.
2. 영역이 둘 이상이면 `| 영역 | 위험 | 봐줄 것 |` 표를 쓴다. 위험은 🔴 판단 필요, 🟡 확인, 🟢 훑기 중 하나이고 🔴 행부터 적는다. 운영 동작, API 계약, DB 마이그레이션, 권한 변경은 🔴이다.
3. `**되돌리기:**` 뒤에 쉬움 또는 어려움과 이유를 한 문장으로 쓴다. 마이그레이션, 데이터 변경, 외부 발송과 공개는 어려움이다.
4. `**검증:**` 뒤에 실제로 돌린 명령과 결과를 한 줄로 쓴다. 돌리지 않은 것은 쓰지 않는다.

AI 리뷰 결과는 본문에 적지 않는다.

## 2. 규칙 8개로 점검한다

제목과 본문을 기준 문서의 규칙 1부터 8까지 하나씩 대조하고, 어긋난 곳을 고친다. 8개를 모두 확인해야 다음 단계로 간다.

## 3. PR을 연다

`gh pr create --base develop`로 연다. 본문은 `--body-file`로 넘기고 `gh pr view`로 base를 확인한다. 열고 나면 CI가 리뷰를 남긴다.
